# Changelog

All notable changes to Stux.Design Status (status.stux.design) are documented here. This
project adheres to [Date Versioning](https://datevers.ing) since v26.10.23 (`YY.MM.DD`, the UTC release date, with `-1`, `-2`… for later releases the same day); earlier releases used [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## v26.11.06-2

### Added

- `.github/workflows/ci.yml`, which runs `bash tests/version.sh` on pushes to `main` and `test` and on pull requests into `main`, so the pull request from `test` has a check to pass.

### Changed

- README (Versioning) and CONTRIBUTING (a new Branches section) say work happens on `test`, reaches `main` only through a pull request that needs CI to pass and is reviewed and merged by Leo, and that releases are committed and tagged on `test`. The commit scripts' push hint says `test`.

## v26.11.06-1

### Added

- Monitors for **Stux.Design Services** (in the Stux.Design group) and a new **Templates** group monitoring
  **Stux.Design Soonpage**, **Maintenancepage** and **Servicepage**. All four serve now, so they replace the
  unchecked "On the drawing board" links.

### Changed

- `README.md` and `CONTRIBUTING.md` brought up to date: what's monitored, the full name Stux.Design Status, and where
  the badge-icon logo comes from.

### Removed

- The "On the drawing board" group, whose sites are all live and monitored now.

## v26.11.06

### Changed

- The page's logo and favicon are now its own badge icon (the Stux.Design mark with a heartbeat badge), as on
  services.stux.design, rather than the plain Stux.Design logo. The README's header too, now titled Stux.Design Status.
- The templates under "On the drawing board" use their full names: Stux.Design Soonpage, Maintenancepage and
  Servicepage.

## v26.10.23

### Added

- `tests/version.sh`, which checks that `VERSION.md` is a valid Date Version, a real calendar date not in the future, and the same as the newest entry in this changelog

### Changed

- Switched from Semantic Versioning to [Date Versioning](https://datevers.ing): releases are numbered by their UTC release date as `YY.MM.DD`, with `-1`, `-2`… for later releases the same day. This release follows v1.0.2
- `commit.sh` and `commit.bat` refuse a `VERSION.md` that isn't a valid Date Version or is dated in the future (UTC), and warn when it's dated before today
- `README.md` and `CONTRIBUTING.md` describe Date Versioning and the release steps

## v1.0.2

### Changed

- The logos and icons in the Markdown docs (README and the like) follow GitHub's light or dark theme, using each brand's `logo-light`/`logo-dark` and `icon-light`/`icon-dark` files

## v1.0.1

### Changed

- The logos and icons in the Markdown docs (README and the like) follow GitHub's light or dark theme, using each brand's `logo-light`/`logo-dark` and `icon-light`/`icon-dark` files

## v1.0.0

### Added

- Stux.Design's status page at [status.stux.design](https://status.stux.design), built with [GitHup](https://githup.stux.group) in Stux.Design magenta (`#e71081`): the Stux.Design website and media CDN are checked every 5 minutes, and the Services site and page templates are listed "On the drawing board" until they serve
- The Boring Legal Stuff hub, 404 page and sitemap, generated by GitHup from the `legal:` block in `.githup.yml`
- The live status table in this README and a status badge, both read from `data/summary.json`
